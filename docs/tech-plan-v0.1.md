# 王者荣耀对局决策建议系统 — 技术方案 v0.3

> 目标：在当前版本、当前已知信息下，对每个决策时机输出后推 10–20s 的近似最优决策建议（人执行，AI 不操作）。

---

## 1. 目标定义（已冻结）

| 项 | 定义 |
|---|---|
| 输入 | 当前可观测状态：小地图、位置、血量/蓝量、技能 CD、装备经济、塔/龙/兵线、可见敌人位置与朝向 |
| 决策粒度 | 决策级宏观动作，约 0.5–1s 重算，事件触发优先 |
| 搜索时域 | 后推 10–20s，末端用价值函数封顶 |
| 输出 | top-1 决策建议 + 依据（保守推演结果摘要） |
| 最优含义 | **候选动作集合内的最优**（候选集设计即最优边界） |
| 信息假设 | 只用当前已知信息，不建模迷雾中的未知状态 |
| 对手建模 | 离线行为先验 + 对局内在线适应（见 5.1），用于提升 rollout 与"最优解"质量 |
| 英雄适配 | 全部策略组件按英雄条件化：候选集、价值函数、行为模型均与英雄绑定（见 5.2），不同英雄的"最优解"定义不同 |

## 2. 决策口径（伤害与随机性）

- 我方伤害：**暴击率视为 0**（我方输出取下界）。
- 敌方伤害：**期望伤害** = `基础 × (1 + 暴击率 × (暴击倍率 − 1))`。
  - 注意口径：暴击倍率存"总倍率"（如 200%），公式如上；若数据源只给"额外暴击伤害"，则用 `基础 + 暴击率 × 额外暴击伤害`。
- 其余随机项（如有）同样按保守/期望双档处理，做成配置项：
  - `enemy_damage_mode = expected | max`（max = 敌方必暴击，最保守档）。
- 所有公式常数（减伤 602 式、穿透、真伤、韧性等）进入版本化数据文件，代码内零硬编码。

## 3. 系统架构

```
┌─ 数据层（版本化，低耦合）─────────────────────────────┐
│ hero_data/{version}/heroes.json       英雄属性/技能数值/成长  │
│ resource_data/{version}/map.json      地形/塔/野怪/龙/兵线    │
│ formulas/{version}/damage.json        伤害结算公式参数        │
│ ui_templates/{version}/               录屏识别模板（血条/CD/小地图）│
└──────────────────────────────────────────────┘
        │ 只读接口（schema 稳定，内容随版本可改）
        ▼
┌─ 确定性世界模型（模拟器核心）──────────────────────────┐
│ 移动/转向/普攻/技能 CD/伤害结算/资源点计时/塔仇恨/护盾控制  │
└──────────────────────────────────────────────┘
        │ rollout（10–20s，我方无暴击、敌方期望伤害）
        ▼
┌─ 决策搜索 ──────────────────────────────────────────┐
│ 英雄条件候选生成 → 束搜索 / 小规模 MCTS → 时域最优     │
│ 末端价值函数：英雄条件化（先手写，后学网络，见 5.2）    │
│ 对手模型：离线行为先验 + 对局内在线适应（见 5.1）        │
│           → 档位2 局部最坏反应作为安全分支               │
└──────────────────────────────────────────────┘
        │
        ▼
   决策建议 + 依据（给真人看，不执行）
```

### 3.1 状态编码（模型与信息低耦合的关键）

模型消费的是**地图坐标系的标准化特征**，不消费版本相关的原始数值：

- 位置：统一地图坐标系（单位），来源=录屏地形定位；
- 实体：hero_id / monster_id / tower_id（ID 表由数据层提供，模型不感知数值）；
- 状态：HP/MP 百分比、技能 CD 剩余秒数、等级、经济差；
- **hero_id 进入模型入口**：共享编码器 + 英雄嵌入（hero embedding），策略组件按 hero_id 条件化；
- 每个样本带 `version` 标签；版本切换只换数据层，特征接口不变，模型可增量再训练。

### 3.2 候选宏观动作集（下一阶段第一设计任务）

原则：**b 控制在 4–8**，每个动作持续 1–2s，才能让 20s 时域（深度 10–20）保持可搜索。

候选集设计规范：
- 语义层：进攻/后撤/打龙/清线/蹲守/回防/换线/回城…
- 参数层：目标点（地形锚点网格）、目标对象（可见敌方/野怪/塔）、技能序列；
- **按英雄模板生成**：候选集 = 职业通用模板（战士/射手/法师/刺客/坦克/辅助）× 英雄专属参数（技能连招、射程、位移、刷野/保排等），不同英雄候选集不同；首版只覆盖锁定英雄子集；
- 每个候选在进入搜索前必须能被世界模型执行（可仿真性校验）。

## 4. 数据获取与标注

### 4.1 结构化数据（版本适应）

- 英雄：官方站抓取 API 为底，补技能数值/成长（社区数据源逐版本比对）；
- 资源点：野怪刷新时间、龙/塔属性等公开表；
- 地形：以游戏地图资料建模为栅格/多边形 + 锚点（塔基、墙体角点、草丛边界、龙坑）；
- 原则：**数据即配置**，全部 JSON/CSV + version 目录；schema 变更走迁移，不回改代码。

### 4.2 录屏识别（状态获取）

- 目标精度：**位置误差 ≤ 半个身位**；
- 定位方法（用户指定）：地形参照定位——先对地形建模并建立锚点集，逐帧识别锚点 → 估计透视变换（homography）→ 把屏幕坐标映射回地图坐标系，实时标注实体位置；
- 辅助信号：小地图图标模板匹配（全局位置粗定位）+ 朝向/位移滤波（平滑与遮挡补齐）；
- UI 识别：血蓝条像素比例、技能 CD 图标模板、经济/击杀 OCR；
- 版本适配：UI 模板与锚点随 `ui_templates/{version}` 更新；
- 验收协议：每版本取 N 段带人工标定真值的录屏，误差统计必须 ≤ 半身位（换算成地图单位后）。

### 4.3 真人残局标注（决策标签）

- 定义（用户确认）：**高水平真人观看结构化残局状态，说出下一步决策**，不是真人实操；
- 状态来源优先级：录屏解析出的真实对局残局 > 模拟器生成残局；
- 标注格式：`{state_id, version, expert_id, decision_class ∈ 候选动作集, reasoning}`；
- 一致性：多人标注同一状态，分歧样本单独仲裁；标注类别必须与 3.2 候选集严格同构，否则标签不可用于策略/价值训练；
- 用途：① 训练/校准对手行为模型；② 校准价值函数；③ 评估搜索输出的合理性。

## 5. 训练对象（纠正后的定义）

"最优解"由搜索计算，不由训练产生。可训练组件只有：

| 组件 | 输入 | 输出 | 数据来源 |
|---|---|---|---|
| 末端价值网络 | t+20s 标准化状态 + hero_id | 该英雄视角的局势价值 | 模拟器自对弈 + 录屏真实数据 + 专家标注 |
| 对手/队友行为模型 | 状态 + 目标英雄 hero_id | 该英雄下一步宏观动作概率 | 离线先验：录屏解析数据；对局内：在线适应（见 5.1） |
| （可选）候选生成策略网络 | 状态 + hero_id | 该英雄的候选动作先验 | 专家标注 + 自对弈 |

训练流水线先以**模拟器自对弈**闭环，录屏数据接入后再校准真实分布。

### 5.1 对局内在线对手适应（提升"最优解"质量）

搜索质量的上限由对手模型决定：rollout 里预测的敌方动作越接近其真实行为，"10–20s 最优解"越可信。因此对手模型分两层：

- **离线先验 B₀**：用录屏解析数据按 `(英雄, 段位区间, 对局阶段)` 训练行为策略，作为通用对手分布；
- **对局内在线适应 B(z)**：对每个可见敌人维护低维风格隐变量 z（激进/保守、刷线/游走倾向等，8–16 维），用本局已观测的 `(状态 → 实际动作)` 序列持续更新其后验。

在线更新机制（按证据量由弱到强）：

1. **解析式更新**：softmax 策略 + 隐变量先验，可做增量贝叶斯/最大似然更新，毫秒级、无遗忘风险，冷启动安全；
2. **小参数微调**：只微调行为模型的 adaptor 层/最后若干层，配当前对局经验回放；
3. **信任门控**：用更新不确定性控制"离线先验 vs 在线适应"的混合权重——样本少（对局前几分钟）时近乎 B₀，样本多时向 B(z) 倾斜，避免被个别噪声动作带偏。

与搜索的集成：

- rollout 中每个敌方节点分支 = 在线适应模型 top-k 动作 + 保留一个"技能可达范围内的最坏反应"安全分支（与 2 节保守口径一致）；
- 每 2–5s 或每次重大事件（阵亡/换线/团战开始）触发一次更新；单英雄一局可观测样本约数百个，足以更新低维 z，不足以从零学策略——**所以离线先验是前提，在线只是适配**。

方法参照：RTS 通用对手建模（[Generic opponent modelling approach for real time strategy games](https://www.infona.pl/resource/bwmeta1.element.ieee-art-000006670714)）、层次化对手建模与规划（[arXiv 2406.08002](https://ar5iv.labs.arxiv.org/html/2406.08002)）、搜索+生成式对手建模（[IJCAI 2025](https://mlanthology.org/ijcai/2025/li2025ijcai-combining/)）。

**验收口径**：对同一段对局，在线适应后的敌方动作 top-3 命中率 ≥ 离线先验；且替换模型后搜索输出的建议在专家盲评中不劣于纯先验版本。

### 5.2 英雄适配（每个英雄的"最优解"不同）

不同英雄的胜率函数、候选动作、风险偏好都不同（射手价值≈输出空间与安全站位，打野价值≈节奏与资源控制，辅助价值≈视野与保排）。因此**没有一个通用"最优解"，只有 hero_id 条件下的最优解**。

实现分三层，全部建立在数据层 hero_id 之上：

1. **英雄嵌入（hero embedding）**：共享状态编码器输出 + 可学习 hero embedding，作为价值/行为/候选生成所有头的条件输入；版本更新英雄数值时只换数据层，embedding 语义保持稳定；
2. **职业先验 + 英雄专属 adaptor**：六个职业（战士/射手/法师/刺客/坦克/辅助）各一套基础参数，每个英雄在职业先验上做小参数 adaptor——解决 120 英雄的冷启动与数据不均衡问题；
3. **英雄条件候选集**：3.2 的候选模板按 hero_id 实例化，保证"候选动作集合内的最优"对每个英雄都有意义（例：辅助不会出现"单人开龙"候选）。

先例：绝悟用统一 actor-critic 网络 + 英雄条件输入覆盖 40+ 英雄（[JueWu 论文](https://arxiv.org/abs/2011.12692)："a unified actor-critic network architecture to capture the playing mechanics and actions of different heroes"）；异构智能体 RL 的独立策略范式见 [HARL](https://developer.volcengine.com/articles/7533523266711846921)。角色级特征对胜负预测有区分度亦有实证（[LoL 按角色胜负预测](https://github.com/KyungRyeolBaek/LoL-Match-Prediction)）。

**首版策略**：每职业锁 1–2 个英雄做全链路（数据→模拟器→搜索→模型），跑通后再扩展英雄池；不追求首版覆盖全部英雄。

## 6. 分阶段实施

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| P0 | 版本锁定 + 数据 schema + 公式入库 + 首版英雄子集锁定 | 数据结构化文件可被读入并生成测试结算结果 |
| P1 | 确定性模拟器核心（首版英雄子集，2 英雄对局起步） | 双方对拼 10s 推演结果与手算一致 |
| P2 | 英雄条件候选集 + 束搜索 + 手写末端价值 | 每 0.5s 输出一条建议，延迟 ≤ 300ms |
| P3 | 英雄条件价值网络 + 对手行为模型（模拟器数据） | 搜索建议胜率 ≥ 纯规则基线 |
| P4 | 录屏识别管线 + 精度验收 | 位置误差 ≤ 半身位，UI 识别达标 |
| P5 | 专家残局标注 + 真实数据训练 | 真实对局状态下的建议质量评估通过 |
| P6 | 对局内在线对手适应 + 搜索集成 | 在线适应后敌方动作 top-3 命中率 ≥ 离线先验，建议质量不劣化 |

## 7. 风险清单

1. **地形定位误差**：透视变化、特效遮挡、皮肤/画质差异 → 锚点冗余 + 多帧滤波 + 版本模板分库；P4 验收不过则回退为小地图粗定位 + 主画面局部相对定位的降级方案。
2. **候选集与专家标签不同构** → 标注前先冻结候选集 v1，标注协议由候选集自动生成。
3. **模拟器保真度不足** → 用真实录屏数据持续校准伤害/移动参数（参数回归）。
4. **版本更新** → 数据层隔离，P0 起全部带 version；版本发布流程 = 更新数据 → 回归测试 → 模型微调。
5. **在线对手适应样本稀缺/过拟合** → 强离线先验 + 只更新低维隐变量或 adaptor 层 + 不确定性门控；禁止在对局内重训主网络。
6. **英雄数据不均衡/冷启动** → 职业先验 + 英雄 adaptor + 首版只锁英雄子集；扩展英雄池走"数据补充 → 微调 → 回归"流程。
7. **合规**：只做离线录屏分析与建议展示，不做客户端注入/自动化操作；上线形态再单独评估。

## 9. Transformer 架构（v0.4，已跑通）

### 9.1 注意力二阶权重函数（训练重点）

- 一阶特征 `F(s)`：`hp_diff / economy_diff / farm_diff / dragon_diff / tower_diff / kill_diff`
- 二阶权重 `w(s) = base_w × (1 + γ·softmax(Q(s)·K/√d))`
  - Q = 局势上下文编码（时间、经济饱和度、敌方输出、己方血量、塔差、龙可用）
  - K = 每个价值维度的可学习键
- 训练：logistic 拟合胜负标签，`src/hok_decision/model/attention_value.py`
- 产物：`data/S45/models/attention_value.pt` / `.json`
- Win RTX 5080 实测：acc 0.939；**经济饱和后经济权重 436.7 → 143.1（ratio 0.33）**，符合"15 分钟后经济无价值"的目标形态

### 9.2 GPT 式下一决策 token

- 局势 token 序列：`[CLS, 时间桶, 经济饱和桶, 敌方输出桶, 己方血量桶, 塔差桶, 龙桶]`
- 因果 Transformer → 预测下一决策 token：`attack/retreat/farm/dragon/tower`
- 代码：`src/hok_decision/model/next_token.py`；产物：`data/S45/models/next_token.pt`
- Win 实测：acc 0.952，loss 0.087

### 9.3 后续接入

1. 用录屏解析/专家标注的真实对局序列替换合成数据；
2. 把训练好的注意力权重接入 `ContextualValue`（作为动态权重）；
3. 用 next-token 动作先验替代/增强 `generate_candidates`；
4. 训练与推理均在 Win `E:\py312` + torch cu128 执行，代码随项目同步。

## 10. 装备/技能向量与硬规则（v0.5）

- `equip_details.json`（官方游戏内接口，126 件）→ `items_vector.json`（20 维属性 + 20 维效果 one-hot + category + 适用英雄 + 合成）
- `skills_vector.json`（538 技能：冷却区间、伤害成长、20 维效果 one-hot）
- `search/loadout.py`：装备/技能向量作为**模型权重特征**——出装属性修正面板，生成 4 维 loadout 上下文（攻击/防御/功能/技能强度），接入注意力二阶权重模型 Q
- Win 重训指标（RTX 5080）：
  - acc 0.957；经济饱和权重比 0.25；
  - 红buff 权重随普攻阵容 51.8→124.6；蓝buff 随技能阵容 53.8→111.8；
  - 血量差权重随出装攻击 41.0→58.2；击杀权重随技能强度 12.7→19.3
- 硬规则（`rules/hard_rules.py`，不参与训练，直接约束候选）：
  - 未携带「惩击」不能购买打野类装备（category=jungle）
  - 辅助类装备（category=support）仅辅助职业（hero_type=6）可出

> 硬规则修正（v0.6）：辅助装的判定**不依赖英雄职业**，而是局内角色输入。
> 模型启动时手动输入角色（对抗路/打野/中路/发育路/游走/辅助），写入
> `data/S45/normalized/role_input.json`；`hok-data set-role <角色>` 可设置。
> 规则：role ∈ {游走, 辅助} 才允许购买辅助装。

## 11. 5v5 状态 masked-token 预训练（v0.7）
